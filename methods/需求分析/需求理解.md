# 需求理解

大多数需求翻车，不是实现错了，而是**听懂就错了**——用户嘴上的需求和他真正想要的，往往是两回事。

这张卡是多轮引导式，让 AI 把"一句话需求"追问成"已经想清楚的需求"。

## Prompt

```
这个需求是这样描述的：【写下原始描述，越接近用户原话越好】。

先不要写方案。你是一位资深需求分析师，请通过最多8轮追问，把这个需求真正听懂。每一轮遵守：

1. 每次只问一个问题，根据上一条回答决定下一问，不要一次性抛出问卷；
2. 优先梳理这四个层面：
   - 真实诉求——用户最终想要的价值结果是什么，而不是他提的实现手段；
   - 隐含假设——需求里默认了哪些前提、哪些你以为"当然如此"其实没验证；
   - 利益相关方——谁会用、谁会买单、谁会被影响，各方的目标是否冲突；
   - 现实约束——时间、成本、技术、合规、既有系统的不变量。
3. 每问一次，用一句话说明你更新了对哪个层面的判断；
4. 只问能改变结论的问题；信息足够立刻停止，不要凑满8轮。

追问结束后输出一份"需求理解档案"：
1. 我的原话（用户原始说法）；
2. 真实诉求（一句话）；
3. 已确认的前提；
4. 仍待验证的假设；
5. 利益相关方的目标冲突点（如有）；
6. 最可能改变需求方向的一个未知项。

档案确认后再进入下一步（方案设计/排期/评估）。
```

## 适用场景

一句话需求、带"我觉得""最好是"的口头需求、需求方自己也没想清楚的情况。

## 要点

- 目的：把"手段描述"翻译成"价值结果"，识别隐含假设与未验证前提
- 每轮只问一个问题，用一句话反馈"更新了什么判断"
- 信息足够即停，不凑满轮数
- 产出《需求挖掘档案》，作为后续需求分析/拆解的事实底座
